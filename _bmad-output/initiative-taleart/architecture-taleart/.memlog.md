- (direction) Fast path chosen by user; spine is the only deliverable for now; assumptions tagged for review.
- (decision) AD-1 [ASSUMPTION] Modular monolith: one deployable API and one PostgreSQL database; domain modules as Nx libs under libs/server, each owning its tables behind a public interface. Prevents early service split and modules reaching into each other's tables. Alternative weighed: services from the start (rejected: ops cost before need).
- (decision) AD-2 Two API surfaces: Management API /api/v1 (sessions, read-write, dashboard) and Delivery API /delivery/v1 (zone keys, read published content and write events, all SDKs incl. native). Prevents SDK keys writing content and native/web data paths drifting.
- (decision) AD-3 [ASSUMPTION] Contract-first: OpenAPI 3.1 document in libs/contract is the source of truth; TypeScript types generated from it; native SDKs generate from the same document. Prevents client/server shape drift across web and native.
- (decision) AD-4 Shared schema tenancy with project_id NOT NULL on every content, zone, collection and event table; project access checked against the caller credential, never trusted from the body. Prevents cross-project leaks and post-MVP metering backfill. Alternative weighed: database per project (rejected: self-host complexity).
- (decision) AD-5 [ADOPTED JSON settings] Frame types as data: frame row has type key and JSONB settings validated against a per-type JSON Schema in libs/contract; new type adds registry entry, schema and renderer, no migration; clients skip unknown types.
- (decision) AD-6 [ADOPTED scheme] Status key stored (live, scheduled, ...); HTTP code mapping defined once in libs/contract; Delivery API returns only live content inside its schedule window.
- (decision) AD-7 UUID primary keys from the database; source-system ids only in importer-owned import_links table; re-import updates linked records. Prevents duplicate content and another tool ids leaking into the model.
- (decision) AD-8 [ASSUMPTION] Importer runs as a Postgres-backed job processed by a worker in the same deployable; writes through other modules' public interfaces; validates each another tool record against the live response before mapping; persists an import report.
- (decision) AD-9 [ADOPTED] Dashboard: server-side sessions, http-only cookie. Zone keys: random secrets shown once, stored hashed, rotate and revoke. Delivery API accepts only zone keys; Management API only sessions.
- (decision) AD-10 [ASSUMPTION direct writes] Events: SDKs post to the Delivery API; append-only events table owned by analytics with project_id, zone_id, frame_id, tale_group_id, tale_id, event name, client and server timestamps; metrics computed from events only; event names defined in libs/contract. Queue deferred.
- (decision) AD-11 [ASSUMPTION] Media through a storage port (put, get, delete by key); local-disk adapter default; content stores keys, never paths or URLs.
- (decision) AD-12 [ADOPTED] Terminology map binding in code, schema and API; another tool named only inside the importer module as the source system.
- (decision) NFR-006 [ASSUMPTION] Web SDK first zone content visible within 1.5 s at p75 on a mid-tier mobile over Fast 4G; Web SDK bundle at most 50 KB gzipped; Delivery API p95 at most 300 ms and Management API p95 at most 500 ms at 50 requests per second on a 2 vCPU, 4 GB host; an import of 1,000 tales completes within 30 minutes.

- (decision) User decision 2026-10-22 (AD-15): each tale keeps a published document (what the Delivery API serves) and a draft document (what Tale Studio edits and autosaves), each with its own revision. Autosave, undo/redo and the 409 flow work on the draft; Publish changes copies draft to published with compare-and-set on both revisions; Discard draft resets the draft to the published document; publishing a draft tale (draft to live) also publishes its draft, resuming a paused tale does not. Existing documents become both, at the same revision. Delivery and the SDK read only the published document; keep-as-new-tale copies the draft.
- (decision) Review of story 7.3 (2026-10-22): setting a tale live publishes its draft when nothing of it is published yet, from any status, after re-checking it; a draft that fails is not published and the status answer flags draftNotPublished; publishing a tale with no draft is refused with 409 nothing_to_publish so the published document is never emptied.
- (decision) AD-15 (story 7.6 review, 2026-10-22): emoji is its own MVP element type, separate from the image sticker ('sticker', a PNG, WebP or GIF of the project's media under the AD-11 media rules). An emoji element holds one RGI emoji as text, named by a11y.label (its Unicode name by default, editable; decorative hides it). The server checks it with the RegExp v flag (\p{RGI_Emoji}); the API needs Node.js 22 or later and fails closed at start-up without the flag, and the accepted set follows the runtime's Unicode (ICU) version. Shape, emoji and sticker are additive registry entries: no document version change, unknown types skipped by older SDKs.
