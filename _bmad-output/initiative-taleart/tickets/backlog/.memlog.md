updated: 2026-11-27T20:15

- (direction) User request: add dark mode support on the user profile; by default take the appearance from the user's device system setting (prefers-color-scheme).
- (decision) Default appearance is System: follow the device setting until the user picks Light or Dark explicitly (user's request).
- (requirement) R1: The profile offers Appearance with System, Light and Dark; System is the default.
- (requirement) R2: With System selected, the dashboard shows dark when the device is in dark appearance and light otherwise, and switches live when the device setting changes.
- (requirement) R3: An explicit Light or Dark choice overrides the device setting and survives reload and a new session on the same account.
- (requirement) R4: Dark appearance covers the dashboard shell and the profile page with text contrast at WCAG AA or better.
- (constraint) Constraint: the project's tale and zone theme (ThemeService, Web SDK) is not changed; appearance is per user, not per project.
- (assumption) Assumption: the choice is stored per user account on the server so it follows the user across devices; localStorage is not enough.
- (question) Open question: 'user profile' means the dashboard account/profile page, not a visitor's profile in the Web SDK or Tale Studio. Confirm the page.
- (question) Open question: should the appearance follow the user across devices (server-stored, the assumption) or stay per device (localStorage)?
- (event) Spec drafted by Sofia; self-validation pending user review.
- (decision) User confirmed 2026-11-27: profile page is the dashboard account page; choice follows the user across devices (server-stored); standalone backlog item.
- (event) Spec finalized: open questions resolved by user; ready to commit to main.
