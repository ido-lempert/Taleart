TaleArt Web SDK sample

A host page for trying the SDK. Open it as ?api=<API URL>#zoneKeys=<key>,<key> to place one element per zone key (tak_…, from the zone's Install tab), each under its own heading; the API URL defaults to http://localhost:3333. Each element shows its zone's display, a bar or a banner. Keys go in the fragment (after #), which the browser never sends to a server or in a Referer header.

Add &theme=<JSON> to override the project's theme in the SDK configuration, for example &theme={"ringStyle":"solid","ringColors":["#0000ff"]}. The page passes it to Taleart.init({ theme }) for every zone, or only for the zone slug named by &themeZone=<slug> with configureZone(slug, { theme }); a field set there wins over the project's theme, and an invalid one is ignored with a console warning. One element can also take its own theme property or JSON attribute, which wins over the zone's. See the web-sdk README for every field.

Add &tags=summer,vip to pass the viewer's targeting tags with setTags(tags), or set them below: each element then shows only the tale groups whose tags match (Any or All, set in the group's Audience), and every group without tags. Without tags, every group shows.

No viewer tags: every group shows.

Add #externalUserId=<ID> to the fragment (never the query: the ID stays out of URLs a server sees), or set it below, to tell the SDK who the viewer is with setExternalUserId(id): tale groups targeted to user lists show only when the ID is in one of them. The SDK sends it in a request header, never in the URL. Use an opaque ID, not an email address.

No external user ID: groups with user lists do not show.
